# Mermaid blocks are checked offline with the official Mermaid CLI, held at GitHub's version

A shipped skill can teach an agent to draw Mermaid diagrams for GitHub, as `change-viz` does. GitHub shows an error in place of a diagram whose block does not parse, and some characters quietly cut a label short, so a mistake in the skill's rules or examples reaches every description an agent writes from them. So `just check`, and with it CI on both hosts, renders every top-level `mermaid` block in `skills/**/*.md` with the real Mermaid, through `just check-mermaid`, and fails on any block that does not render. `just check-mermaid` also checks any other Markdown file by hand, such as an agent's recorded output.

The checker, `scripts/check-mermaid.mjs`, drives the official Mermaid CLI, `@mermaid-js/mermaid-cli`, through its exported `renderMermaid`, in one chrome-headless-shell that Puppeteer starts once and every block of the run shares. It names each failure by its opening fence's `path:line` with Mermaid's message, which the CLI's own Markdown mode does not do. It renders with GitHub's `securityLevel: 'antiscript'`, fails a block over Mermaid's 50,000-character `maxTextSize`, and keeps the browser off the network, because a label can hold HTML such as an `<img>`. `package.json`'s `overrides` holds `mermaid` at 12.2.0, the version GitHub's viewer bundle hard-coded when it was read on 2026-11-10. `--labels` prints every label as rendered, to show one that was cut short without an error.

This narrows [ADR 0002](0002-python-core-node-tooling-just-front-door.md): the checker is the one piece of the repository's own code in JavaScript, not Python, because Mermaid renders only in a browser and the CLI's renderer is a Node module. The skill itself still carries rules and no checker: `change-viz`'s `references/rendering-on-github.md` gives each rule with its reason, so following them adds nothing to what the skill needs installed.

## Considered options

- **GitHub's comment preview.** It is the renderer a reader sees, and the planned probe of the skill's rules was to paste blocks into it by hand. The maintainer chose an offline check instead. A real post, as proof on GitHub itself, is [ticket 28](../../.scratch/change-viz/issues/28-render-proof-in-a-github-post.md).
- **A hand-written parser or pattern scan.** Patterns that do not flag valid forms, such as a round node or parentheses inside a quoted label, grow into a partial Mermaid tokenizer, and it follows a grammar read from Mermaid's source rather than Mermaid itself.
- **Rules only.** The rendering rules drafted for the skill and the eval patterns that score its diagram labels were read from Mermaid's grammar, not rendered. Run through the checker, they agreed with Mermaid 12.2.0, and it found two rules they lacked: `#`, a word or number, then `;` is read as an entity code, and `<…>` in a flowchart node label is read as HTML and vanishes. Without a check, a wrong rule ships unseen.
- **A checker bundled with the skill.** It would add an interpreter to a skill that needs only Git, and the draft would reach it either as a file, which the skill forbids writing, or on stdin through a here-doc, whose run the eval harness's `script_ran` cannot always see.

## Consequences

- **A browser in the toolchain.** `just sync`, and so `just initialize`, ends with `just install-browser`, which downloads the chrome-headless-shell build the locked Puppeteer names into `.tools/puppeteer`, about 200 MB on disk. Puppeteer's own postinstall, which would add full Chrome, is denied ([ADR 0003](0003-project-local-toolchain.md)). CI's gate and the manual live-evals job both run `just initialize` with no cache, so each of their runs downloads it again, though the live evals never render a diagram.
- **Chrome's sandbox stays on.** On Ubuntu 23.10 or later it needs the AppArmor restriction on unprivileged user namespaces lifted, as Codex's sandbox does, which CI sets; `--no-sandbox` would trade the sandbox away for a checker that renders agent output.
- **A test holds the version.** `tests/test_check_mermaid.py` checks that the override, the lockfile and the version the rendered page reports all equal the version GitHub ran. A bump of `mermaid`, from Renovate ([ADR 0016](0016-dependency-updates-via-renovate.md)) or by hand, fails `just check` until someone reads GitHub's version again and moves the test with it. A bump of `@mermaid-js/mermaid-cli` leaves Mermaid at the override, and a bump of Puppeteer moves the browser build. Neither is in `renovate.json`'s Node dev tools group, so Renovate proposes each in a pull request of its own.
- **GitHub's version is unpublished.** The check is against the pinned Mermaid, so a block can pass here and fail on GitHub once GitHub moves, or the reverse, and nothing tells the repository when it does.
- **Only fences at the top level.** A fence inside a block quote, or indented under a list item, is not checked. An HTML comment is skipped as GitHub skips it, fence-looking lines included, but other HTML blocks, such as a `<pre>` or a `<details>` up to its first blank line, are read as Markdown: a fence in one is checked though GitHub would not render it, and a fence one leaves open can hide a later block. Tables and the rest of a description's Markdown are not rendered either.
